# Technology decisions

| # | Decision | Alternatives considered | Rationale |
|---|---|---|---|
| T1 | **Rust** for the runtime, scheduler, planner, CLI, and server | C++ (like llama.cpp), C (like Colibrì), Python orchestration (like Colibrì's `coli`) | The orchestrator is concurrent code that hands out borrowed views of buffers which another thread may evict. That is the bug class Colibrì documents repeatedly (use-after-free in `rss_guard`, `ESlot` refcount underflow aborts). Rust's ownership and lifetimes make leases a compile-time property. One static binary, cross-platform. |
| T2 | **GGUF first**, read natively | Safetensors with conversion (Colibrì), ONNX | GGUF is the dominant local format, carries quantization and tokenizer and chat template in one file, and has a published spec. No conversion step means "I downloaded a model, run it". Safetensors comes later through the same `ModelDesc` abstraction. |
| T3 | **Own GGUF parser**, not ggml's | Bind `gguf.c` through FFI | Parsing is ~400 lines. Kestrel needs only offsets, sizes, and metadata, and must parse without loading data. A native parser keeps `kestrel inspect` and `plan` dependency-free and fast. |
| T4 | **Native Rust CPU executor** plus a **llama.cpp adapter** | Only llama.cpp via FFI; only native | Streaming and prefetch need control over every weight access, which the native executor provides. GPU kernels come from ggml through llama.cpp. Writing CUDA kernels is a non-goal. See [backend-strategy](backend-strategy.md). |
| T5 | llama.cpp integration through **process + CLI parameters** in the MVP, FFI later | `llama-cpp-sys` FFI | The llama.cpp C API changes frequently. A process boundary keeps Kestrel buildable without a C++ toolchain or CUDA SDK, and the placement knobs (`-ngl`, `-ot`, `--mlock`, KV type) are all exposed on the CLI. FFI is the phase-9 step toward Kestrel-owned residency on GPU. |
| T6 | **Positional reads** (`pread` / `seek_read`) with an **I/O thread pool**, `O_DIRECT` where available | mmap; io_uring | mmap gives up control over eviction and readahead, and its RSS is invisible to Kestrel's ledger. That was Colibrì's "mmap RSS bug" (`c/st.h` header). A thread pool is portable (Linux, Windows, macOS) and reaches NVMe queue depth. io_uring is a Linux-only optimization to add behind a feature flag once it is measured. |
| T7 | **rayon** for compute parallelism | OpenMP-style manual threads | Work-stealing parallel loops over output rows. The thread count is capped to physical cores, since memory-bound GEMV regresses with SMT (Colibrì `docs/tuning.md`). |
| T8 | **axum + tokio** for the HTTP server | hyper directly, actix, tiny_http | Mature, supports SSE streaming for `stream: true`. Inference runs on a blocking thread and does not hold the async runtime. |
| T9 | **minijinja** for chat templates | Hand-written templates per model | GGUF ships the model's Jinja chat template. Rendering it generically is the only scalable approach. |
| T10 | **fancy-regex** for GPT-2-style pre-tokenizers | `regex` (no lookaround) | The GPT-2 / Llama-3 / Qwen pre-tokenizer patterns use `\s+(?!\S)` lookahead. |
| T11 | **clap** CLI, **serde/serde_json** everywhere | — | Standard. Every report (hardware, inspect, plan, metrics, benchmark) has `--json`. |
| T12 | **Hardware discovery without heavy dependencies**: `/proc`, `/sys`, `nvidia-smi`/NVML query, `sysinfo`-style Windows APIs through `std` plus a few `cfg` FFI calls | `sysinfo` crate, `nvml-wrapper` | Keeps the dependency tree small. GPU discovery shells out to `nvidia-smi --query-gpu` (always installed with the driver), with NVML dynamic loading as the upgrade path. Absence of a GPU is a normal result, not an error. |
| T13 | Measured micro-benchmarks cached in JSON per machine fingerprint | Theoretical bandwidth tables | The brief requires real measurements. The fingerprint (CPU model, RAM total, GPU list, storage device) invalidates stale caches. |
| T14 | License: **Apache-2.0** | MIT | Patent grant. Compatible with llama.cpp (MIT) and Colibrì (Apache-2.0). |
| T15 | No telemetry, no network by default | Opt-in telemetry | The brief requires local-only. The only network code path is an explicit model download. Local-only is enforced by having no HTTP client in the default build. |
